## Pre-extraction reference

Before editing engine boundaries, the full M1 application was compiled with its
existing `CIVIC89_MILESTONE_TESTS` entry path and SDL dummy/software renderer.
Additive instrumentation consisted of `seedSimulationRandom()` after the existing
RNG definition, `EngineDigest.h/.cpp`, and [M2Capture.cpp](M2Capture.cpp) in place of
the milestone test body. No load, phase, map, sprite, budget or disaster algorithm
was changed. The temporary target used all 47 M1 application sources, the existing
SDL/image/ttf/nfd/JSON/Shlwapi links and Release `/fp:fast`.

Reproduction: archive/check out M1 `de424f3` in an isolated directory; add the seed
declaration/function and the digest files from this branch; build the probe as
`civic89_parity_capture` with the above definition and M1 source list. Run each
case in a fresh process from its staged asset directory:

```powershell
$env:SDL_VIDEODRIVER = 'dummy'
$env:SDL_RENDER_DRIVER = 'software'
$env:CIVIC89_CAPTURE_SCENARIO = '6'
$env:CIVIC89_CAPTURE_TICKS = '16384'
./civic89_parity_capture.exe
```


## Compatibility limits

See [ADR 0003](../../project/decisions/0003_M2_ENGINE_BOUNDARY.md). No normal-play
RNG/distribution, simulation algorithm or writer-format change is intended.
Invalid city acceptance is deliberately tightened. Existing valid-city history
reset behavior, historical 16-bit format import, atomic save handling and wider
resource/audio work are deferred to M3. No new desktop/DPI compatibility claim
is made; automated native tests use SDL dummy/software rendering. Upstream
history/licences/tag/remote and all asset provenance remain intact.
